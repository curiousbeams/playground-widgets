---
title: Wolfram Language
---

Embed interactive Wolfram Language output with the `{wolfram}` directive from
`plugins/wolfram.py`. Each cell resolves to a **public Wolfram Cloud object** that
renders client-side via the
[wolfram-notebook-embedder](https://github.com/WolframResearch/wolfram-notebook-embedder)
— readers never need a Wolfram Engine. Prose, headings, and cross-references stay
in MyST; only the interactive *output* is Wolfram-rendered.

The expression to deploy is **tagged** with a full-line comment marker:
`(* #| deploy *)`, or `(* #| label: app:my-widget *)` to also make the widget a
cross-reference target. Lines above the marker are setup; the region below it is
evaluated and its value deployed. **Untagged cells are definitions-only** — they
run in the page session (and can be echo'd) but embed no widget. The `:echo:`
code fence is MyST's rendering of the *input* (marker lines are hidden); the
deployed cloud object contains only the *evaluated result*, so the two compose
without any cell-hiding tricks.

All cells on a page share **one kernel session** at deploy time, evaluated in
document order — later cells see definitions from earlier ones. Cell digests are
chained (cell $N$'s digest covers cells $1..N$), so editing an earlier cell
correctly invalidates the deployments of everything after it. Renaming a
`label:` never re-deploys; moving the marker does.

A cell's cloud URL is resolved in order from:

1. an explicit `:url:` option,
2. the committed cache manifest `.jupyter-book-wolfram/deployments.json`
   (keyed by the chained digest, so builds are reproducible with **zero**
   Wolfram tooling),
3. an opt-in `CloudPublish` via `wolframscript`
   (only when `JUPYTER_BOOK_WOLFRAM_DEPLOY=1` **and** a licensed `wolframscript`
   is available — never on CI).

Otherwise the cell renders a warning placeholder instead of failing the build.

## 1. Explicit `:url:`

Point a cell at an already-published cloud object (your co-author can
`CloudPublish` straight from Mathematica and paste the URL):

```md
:::{wolfram}
:url: https://www.wolframcloud.com/obj/gvarnavi/VisualGuideMaterialsScience/MySTSnippets/wolfram-bfa107381d28d50e
:echo: true
:max-height: 640

Manipulate[
 Plot[Sin[a x], {x, 0, 2 Pi}],
 {a, 1, 3},
 SaveDefinitions -> True]
:::
```

:::{wolfram}
:url: https://www.wolframcloud.com/obj/gvarnavi/VisualGuideMaterialsScience/MySTSnippets/wolfram-bfa107381d28d50e
:echo: true
:max-height: 640

Manipulate[
 Plot[Sin[a x], {x, 0, 2 Pi}],
 {a, 1, 3},
 SaveDefinitions -> True]
:::

## 2. Cached deployment (manifest hit)

This cell tags its output with a bare `(* #| deploy *)` marker. Its digest is
recorded in `.jupyter-book-wolfram/deployments.json` (deployed once by a
`JUPYTER_BOOK_WOLFRAM_DEPLOY=1` build), so ordinary builds render it without
any Wolfram tooling:

:::{wolfram}
:echo: true
:max-height: 640

(* #| deploy *)
Manipulate[Plot[Sin[a x], {x, 0, 2 Pi}], {a, 1, 3}]
:::

## 3. Definitions-only cells and shared definitions

An **untagged** cell contributes definitions to the page session without
embedding a widget — here we define `pi`, echo'd but with no output:

:::{wolfram}
:echo: true

pi = 2 Pi;
:::

Cells share one kernel session in document order, so `pi` is defined in the
next cell. Its marker carries a **label**, making [this sine widget](#app:sin-pi)
a cross-reference target. At deploy time `IncludeDefinitions -> True` bakes `pi`
into the published object, so the embedded widget works standalone:

:::{wolfram}
:echo: true
:max-height: 640

(* #| label: app:sin-pi *)
Manipulate[Plot[Sin[a x pi], {x, 0, 2 Pi}], {a, 1, 3}]
:::

## 4. Numbered figures

Adding a `:caption:` option wraps a labeled widget in a MyST figure — numbered
and referenceable like any other figure: see [](#app:sin-over-pi).

:::{wolfram}
:echo: true
:max-height: 640
:caption: An interactive sine plot with the frequency scaled by 1/π — sliders stay live.

(* #| label: app:sin-over-pi *)
Manipulate[Plot[Sin[a x / pi], {x, 0, 2 Pi}], {a, 1, 3}]
:::

## 5. Not yet deployed (manifest miss)

An unrecorded cell degrades to a warning with the code preserved — the build
never fails. The digest shown in the box is what `--record` expects. (This demo
cell carries `:defer: true`, which keeps it out of deployment even on
deploy-enabled builds — also handy for draft cells you aren't ready to publish.)

:::{wolfram}
:defer: true

(* #| deploy *)
DensityPlot[Sin[x y], {x, -2, 2}, {y, -2, 2}]
:::

## Authoring guidelines

- Tag the expression to deploy with `(* #| deploy *)` or
  `(* #| label: app:my-widget *)` on its own line; everything above the marker
  is setup, everything below is deployed (its last expression's value — the
  deploy driver warns if it evaluates to `Null`, e.g. from a stray trailing `;`).
- Untagged cells are definitions-only; there is no widget and no placeholder.
- Add `SaveDefinitions -> True` to a `Manipulate` that uses helpers, so the
  deployed object is self-contained. The deploy driver also passes
  `IncludeDefinitions -> True` to `CloudPublish` as a backstop.
- Prefer discrete/simple controls: those run largely client-side, while
  kernel-backed `Dynamic` evaluations round-trip to the cloud and consume the
  *deployer's* Cloud Credits.
- Labels are cross-reference targets (`[text](#app:my-widget)`); with a
  `:caption:` the widget becomes a numbered figure (`[](#app:my-widget)`
  renders as "Figure N"). Captions are plain text (no markdown/math parsing).
- Full-notebook embeds (`{wolfram-notebook}` with a local `.nb`) accept
  `:hide-input: true`, which closes input cells (`CellOpen -> False`) at deploy
  time — snippet cells never need this since only outputs are deployed.
- Deployment configuration (uni-VPN machines only):
  `JUPYTER_BOOK_WOLFRAM_DEPLOY=1` enables `wolframscript` deploys;
  `JUPYTER_BOOK_WOLFRAM_CLOUD_PATH` sets the cloud directory (default
  `myst-widgets/`); `JUPYTER_BOOK_WOLFRAM_CLOUD_BASE` pins a shared `CloudBase`
  so all authors publish into the same book directory. Commit the updated
  manifest afterwards.
- To record a deployment made elsewhere (e.g. `CloudPublish` from Mathematica):
  `plugins/wolfram.py --record <url> --digest <digest-from-placeholder>`
  (or `--record <url> --nb notebook.nb` for a full local notebook).
